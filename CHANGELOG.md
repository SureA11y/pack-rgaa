# Changelog

All notable changes to this package are documented here. This project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Unreleased

### Added

- RGAA 4.1.2 as a pack for `@surea11y/core` 1.16 (`~1.16.0`): the standard's criteria and tests, generated from DINUM's criteria file; the RGAA tests each of core's rules checks; one result per RGAA criterion; the `rgaa-4.1.2` profile, which runs only the rules that check an RGAA test, the pack's and core's, and reports RGAA's criteria alone, judged by WCAG 2.1 with 4.1.1 Parsing kept (`keepsParsing`), as RGAA 8.2 requires valid code; 111 opt-in rules for what RGAA requires beyond WCAG or judges differently, their ids starting with `rgaa-`; messages in English and French; and the four probes five of its rules read.
- A finding counts toward the RGAA test it fails, not every test its rule is linked to: a rule-map row can send findings to tests by what they record (`findings`), by reason code (`reasonCodes`), and ask rather than fail where it takes a person (`asks`), and each criterion's result names only the tests of the findings that decided it (core's per-requirement routing, SureA11y/core#269). Contrast failures go to 3.2.1, 3.2.2, 3.2.3 or 3.2.4 by text size and weight, invalid list markup to 9.3.1 or 9.3.2 by the list, unnamed widgets to 7.1.1 or 11.6.1 by role (a progress bar or meter to neither), and an image without alt fails 1.1.1 and is asked about under 1.2.1.
- Every undecided finding of the pack's rules says how to answer it: each rule lists the reason codes it gives (`meta.reasonCodes`) and, for each code it asks about, the steps a person follows from the element the finding names, with what they see if it passes and if it fails (`meta.review`), which core 1.14 gives as `howToCheck` and the HTML report as "How to check". The steps are in English, as core gives a pack's; `rgaa-contrast-minimum` and `rgaa-valid-lang` take core's, in every locale.
- Core 1.14's rules have rows in the mapping: `image-of-text` asks under 1.8.2 about an image button, and under 1.8.1 about an `<img>` showing an SVG with text; `invalid-field-error-message` under 11.10.4 and 11.10.7; `live-region-announcements` under 7.5.1 to 7.5.3; `widget-keyboard-focusable` under 7.3.1; and `aria-expanded-state-mismatch` under 7.1.1. `aria-owns-valid`, `control-name-title-only` and `label-for-valid` check no RGAA test, each with the reason, and `label-for-valid`'s labels are `rgaa-label-for-target-valid`'s under 11.1.2.
- `rgaa-script-button-name-present` fails a button outside any form that has no accessible name, under RGAA 7.1.3, which requires a name with no alternative: such a button acts only through script, so it is an interface component. `rgaa-form-button-name-present` keeps the buttons in a form for 11.9.1, so an empty button counts once.
- `rgaa-valid-lang` reports RGAA 8.8.1 in place of `valid-lang`: it is core's `valid-lang` with `codes: 'iso639'`, so a change of language given as an ISO 639-2 code (`lang="fra"`, `"ger"`) or in the `qaa` to `qtz` local-use range passes, as the glossary "Code de langue" allows, where WCAG's rule, judged against the IANA registry, fails it. `rgaa-html-lang-code-valid` (8.4.1) uses core's `isIso639LanguageCode` in place of its own list of codes, and now also accepts `hbs`. Both use the `valid-lang` setting and helper core 1.14.0 added.
- `rgaa-figure-caption-structure` checks every kind of captioned image RGAA 1.9 names, not only `<img>`, `<input type="image">` and `role="img"` (1.9.1): an `<object type="image/…">` (1.9.2), an `<embed>` (1.9.3), an `<svg>` (1.9.4) and a `<canvas>` (1.9.5). Each finding records its figure's first image in `imageKind` and counts toward that image's test.
- `rgaa-css-colors-paired` checks RGAA 10.5: a CSS text color reaching text needs a background color on its element or an ancestor (10.5.1), and a background image a background color (10.5.3); a background color with no text color is asked about (10.5.2). In a browser it reads which elements an author rule sets each on from the cascade, with a sentinel in the weakest cascade layer for one read, so the browser's own colors never count and a style sheet from another origin counts like any other; without a browser it matches the style sheets' selectors, and asks when one cannot be read. It is RGAA's only: WCAG's F24 describes the same pattern, as an informative failure technique rather than a requirement.
- RGAA's methodology, glossary and notes: DINUM's methodology and glossary in `data/`, and the criteria's particular cases and technical notes, which the generator used to drop. Each criterion is a requirement of core's procedures and each test a facet with RGAA's steps, in its theme, related to WCAG as RGAA relates it, so `proceduresFor`, `listProcedures`, `procedureChecklist`, `renderProcedures` and the HTML report's "What's left for a person" read RGAA rather than WCAG. The standard declares French and is read in French in every locale.
- `@surea11y/pack-rgaa/public` adds `RGAA_GLOSSARY`, `rgaaGlossaryFor`, `rgaaCriteriaStatus` (a scan as an audit grid records it, `C`, `NC`, `NA` or `NT`, for all 106 criteria) and `rgaaConformityRate` (DINUM's rate for a sample of pages).
- A scan can judge a page by RGAA and another profile at once (core 1.15).
- The standard as data (`standard-data.js`, core's format `surea11y-standard/1`), built with core's `standardFromData`: core's rollups, entries and validation, its tests under its criteria (`tests`, `wcagCorrespondence`), in place of the pack's own (`mappings.js` keeps only what the procedures read). They give what the pack's own gave, rollup for rollup and rule for rule (`tests/standard.test.js`, against a record taken from the pack's functions with core 1.16.0). A standard built on RGAA, such as RAWeb, starts from the data with core's `deriveStandard` (`standardDataOf(pack.standard)`).
- The `rgaa-4.1.2` profile serves article 47 of law n° 2005-102 (`law`): results name it in `engine.law`, the HTML report shows it, and `describePacks` lists it with whom it applies to and its source. Facts to show, never logic. These, the data and the tests under criteria are experimental in core until 1.18.0, so the pack's range is `~1.16.0`.
- The rules' steps come in English and French, and core's undecided findings read in RGAA's terms under the RGAA profile, in French (`standard.review`). `rgaa-contrast-minimum`'s steps give RGAA's thresholds.
- The rules of the audit against RGAA's tests, methodology and glossary, taking the pack to 80 of 106 criteria and 167 of 258 tests: among them questions for CAPTCHAs, embedded players, navigation systems, unmarked quotations, status messages, tooltips, changes of context and of language, consequential forms and label placement, and rules for images of each kind that may be decorative, table headers, required fields and text direction.

### Changed

- `rgaa-main-element-structure` asks (`mainMayBeInFrame`) rather than fails `noMain` when a page with no `<main>` shows a visible `<iframe>` of 100 by 100 pixels or more: the page may hold the header, navigation and footer around a frame that holds the main content. A person checks whether the frame is the main content zone and whether the document it shows structures it with `<main>`. A hidden frame or a tracker of a few pixels does not count, and such a page still fails.
- `rgaa-html-elements-attributes-valid` fails `scope` on a `<td>` under 8.2.1 (`scopeElement`), which it let through: HTML makes it obsolete, so the attribute does not conform, although the W3C validator only warns about it.
- An RGAA criterion passes only where its rules check all it asks: 2.1, 8.1, 8.3 and 8.5. Every other criterion is `partial` (core's `meta.partial`): `cantTell` where its rules all pass (`composite.rollup.cantTell.partialCheck`) or all find nothing to check (`partialCoverage`), as core 1.14 judges WCAG's criteria, since the rules check only some steps of its tests.
- Findings follow core 1.14's rules where RGAA files them apart: `focus-not-removed-by-script`'s failure, a handler that only blurs an element in the tab order (F55), fails 7.3.2, where it was asked about; a `video-caption` question about a captions track's completeness (`CAPTIONS_REVIEW`) counts toward 4.4.1, the captions' relevance, not 4.3.1; a `valid-lang` failure on an element that sets the page's starting language (`DEFAULT_LANG_INVALID`, `<body lang>` with no `<html lang>`) toward 8.4.1 under `rgaa-valid-lang`, not 8.8.1; and a duplicate id inside one shadow tree (`DUPLICATE_ID_IN_SHADOW_TREE`) fails 8.2.1, as in the document. The mapping's notes say what core's rules do in 1.14 (`form-control-single-label`, `td-has-header`, `table-th-has-data-cells` and `page-title-patterns` ask where they failed or kept quiet).
- Core 1.15 asks where only WAI-ARIA or HTML breaks. A list item outside its list, an `<li>` outside `<ul>`, `<ol>` or `<menu>` or a `<dt>`/`<dd>` outside `<dl>`, stays a failure of 9.3.1 or 9.3.3 (`outcome: 'fail'`), as RGAA names the elements a list is structured with; a stray child inside a list or a description list (`LIST_INVALID_CHILD`, `DL_INVALID_CHILD`, `DL_NO_DT_DD`, `DL_DT_DD_ORDER`) is asked about under the test of its list, since it may be a heading, a separator or a wrapper not presented as an item, and its nesting still fails 8.2.1 through `rgaa-html-nesting-valid`; an unnamed grid, tree, dialog or radiogroup stays a question under 7.1.1 and 11.6.1, which pass through an alternative.
- Markup inside an open shadow root fails 8.2.1 like the rest of the page, with the same reason codes, where it was asked about: a shadow root is part of the generated source (« code source généré »). This covers `rgaa-aria-attribute-conformance`, `rgaa-aria-role-conformance`, `rgaa-html-elements-attributes-valid`, `rgaa-html-nesting-valid` and core's `duplicate-id` (`DUPLICATE_ID_IN_SHADOW_TREE`). One case still asks (`idReferenceOtherTree`): an `aria-activedescendant` whose id names an element only across a shadow boundary. ID references do not cross the boundary, but the validator asks only for an element of the same document. An id found nowhere in the page still fails.
- `rgaa-aria-role-conformance` decides `<img role="presentation">` from the markup instead of asking. With `alt=""` it passes 8.2.1, though the validator reports it, since RGAA 1.2.1 names that markup for decorative images. With no alt it fails (`imgPresentationRole`), as HTML requires alt on an `<img>`. `role="none"`, its synonym, is judged the same way.
- `rgaa-text-direction-marked` fails short text in a right-to-left script where it asked: a run of Hebrew, Arabic or another right-to-left script with two letters or more in a left-to-right context fails 8.10.1 whatever its length (« العربية » in a language menu, a word quoted in a sentence). The test has no exception for short text, and those scripts write only languages read right to left. Text in a `<bdi>` with no `dir` fails too (`bdiWithoutDir`), as a `<bdi>` does not replace the `dir` attribute. The rule still asks about a single right-to-left letter, Arabic-Indic digits, Arabic mathematical symbols, and left-to-right text of one or two words in a right-to-left page.
- `rgaa-main-element-structure` fails a second `<main>` without its own `hidden` attribute that sits in a closed `<details>` or under an ancestor's `hidden="until-found"` (`revealableMain`), where it asked. The user can reveal it with no script, so two `<main>` elements are visible at once, which RGAA 9.2.1's « une balise `<main>` visible unique » rules out. A `<main>` hidden by an ancestor's plain `hidden` or a closed `<dialog>` is still asked about, as only a script shows it.
- `rgaa-aria-attribute-conformance` asks (`emptyIdReference`) rather than fails about an empty ID-reference attribute (`aria-labelledby=""`, `aria-describedby=""`, `aria-activedescendant=""`…). ARIA element reflection (`el.ariaLabelledByElements = [...]`) writes exactly that in Chromium, and keeps the reference in the DOM property, often across a shadow boundary. A person reads the accessibility tree: the attribute passes 8.2.1 if the relation is exposed there, and fails otherwise. A value of whitespace only, or an `aria-activedescendant` naming no element of the page, still fails.
- The question about a `<main>` hidden by an ancestor's `hidden` or a closed `<dialog>` (`rgaa-main-element-structure`, `hiddenByAncestor`) now gives RGAA 9.2.1's verdict. It passes when, in normal use, this `<main>` is never shown with the other one, because the script that reveals it hides the other. It fails when both can be visible together. The missing `hidden` attribute still fails 8.2.1.
- A document shown in a frame is no page of its own: the rules on doctype, language, title, skip links, zones and the main element leave it alone, as core's do.
- `rgaa-field-label-listed-source` fails a field whose only label is a `<label>` wrapping it without `for` (`wrappingLabel`), as RGAA 11.1.1 names « une balise `<label>` ayant un attribut `for` »; it asks (`wrappingLabelAdjacentButton`) when a button sits next to the field or its label, where the fifth condition, an adjacent button with a visually hidden `<label>`, may apply. A `<label for>` pointing at an element a label cannot name fails (`labelForNotLabelable`), except on a custom element, which may be form-associated and is asked about (`labelForCustomElement`). An `<output>` that belongs to no form is no longer checked, as the glossary makes a field an « objet d'un formulaire » and its message is judged under 7.5; one in a form, or joined to one by its `form` attribute, fails without a label whether or not it is announced (`outputStatus` is gone).
- `rgaa-form-button-name-present` fails a nameless button outside a form that joins it through its `form` attribute (`formAttributeOnly`), where it asked: the attribute makes it a button of that form (glossary « Bouton (formulaire) »), so RGAA 11.9.1 applies. An image button with no alt joined this way is asked about as `imageButtonNoAlt`, like one inside a form.
- `rgaa-required-field-indication` fails a required field whose only indication is a « tous les champs sont obligatoires » sentence not linked to it (`allFieldsRequiredSentence`), where it asked: the particular case of RGAA 11.10 keeps 11.10.2 applicable when all the fields are required, and the field's label and linked passages show nothing. Linked by `aria-describedby` or `aria-labelledby`, the sentence passes. A sentence with an exception (« sauf mention contraire », « except », « unless ») is still asked about (`allFieldsRequiredWithException`), as the form may mark its optional fields in words the rule does not read. A field's own label, its `<label>` or `aria-labelledby` passage, now counts where the form marks its optional fields, and a page whose styles were not read is asked about before the sentence is judged.
- The four label-in-name rules read « contient » as words and excuse only what RGAA's particular cases excuse (punctuation, capital letters, symbols): a name that writes out an abbreviation, gives a visible word another ending ("Rechercher" for "Recherche") or leaves out text in parentheses shown in the label now fails 6.1.5, 7.1.3, 11.2.5 or 11.9.2 (`NAME_LACKS_VISIBLE_LABEL`, or `SOURCE_LACKS_VISIBLE_LABEL` for a link's other sources) instead of being asked about. `POSSIBLE_ABBREVIATION`, `PARENTHESISED_TEXT_MISSING` and `POSSIBLE_INFLECTION` are gone; a visible label that may be a symbol is still asked about (`POSSIBLE_SYMBOL`).
- `rgaa-field-label-in-name-sources` and `rgaa-form-button-label-in-name-sources` judge only the source that gives the accessible name, as 11.2.5's methodology, the glossary « Étiquette de champ de formulaire » and 11.9.2's methodology do: a title, or a source that aria-labelledby or aria-label overrides, that lacks the visible label no longer asks, and the field or button passes. Their `SOURCE_LACKS_VISIBLE_LABEL` code is gone. Links still have every source checked (6.1.5 methodology).
- `rgaa-link-content-label-present` fails a link whose only content is text generated by CSS (`::before`, `::after`) under RGAA 6.2.1 (`generatedTextOnly`), where it asked: the glossary « Intitulé de lien », note 5, does not count such text as content between `<a>` and `</a>`. An embedded element, an element named by its own `aria-label`, or hidden text beside a name from an attribute is still asked about.
- `rgaa-link-title-content-name` decides composite links under RGAA 6.1.3: a title that holds the link's text and the text alternative of each of its images, as whole words in any order (punctuation and capital letters aside), passes, and one that leaves out an alternative fails (`compositeLinkTitle`), where both were asked about. A title that leaves out only a one-character alternative, which may be a symbol, is still asked about (`compositeSymbolAlternative`).

### Fixed

- `rgaaConformityRate` throws a `RangeError` for a criterion the version doesn't have, which it counted (`99.9` made a rate of 0.5), and for a page that is not a list of rows or `{ rows, process }`, or a row that is no object, where it threw a `TypeError` or counted nothing. `rgaaCriteriaStatus` reads a scan across frames (`{ topFrame, frames }`) through its `topFrame`, where it gave `NT` for every criterion; the frames' own scans are not merged in.
- `rgaa-headings-absent-review` and `rgaa-navigation-systems-review` are notApplicable on a scan of part of a page (a `contextSelector` or `engineOptions.fragment`), as the pack's other page-level rules are, where they asked about the page's `<body>`, outside the part scanned.
- Four rules no longer slow down with the square of a page's fields: `rgaa-navigation-systems-review` gathers the page's `<label for>` once rather than for each field, `rgaa-field-label-listed-source` puts the fields in document order without comparing their positions pair by pair, and `rgaa-label-placement-review` and the label-in-name rules read and measure a label, and check whether an element is seen, once however many fields share it. At 4,000 fields, `rgaa-navigation-systems-review` takes 14 ms where it took 2.8 s, and 4,000 fields named by one large `aria-labelledby` take `rgaa-label-placement-review` 50 ms where they took 6.7 s. Results are unchanged.
- The four label-in-name rules read a visible label as the browser renders it: a word split across inline elements stays one word, where they put a space inside it (`Télé<b>charger</b>` read "Télé charger" and failed 6.1.5 against `aria-label="Télécharger"`). A space separates two runs of text only where the source has whitespace, a line break, a form control or a block boundary. Their summaries name "this link", "this form field", "this button" or "this component" rather than starting with a bare tag name.
- `rgaa-page-title-unique` and `rgaa-frame-title-relevant` quote a title cut to 80 characters ("..." after the first 77), as the pack's other rules quote text, in the summary, the message parameters and the details: an 80 KB title made an 80 KB finding. Titles are still compared whole.
- `rgaa-focus-indicator-contrast` gives the elements it focuses the style of the browser's focus ring (`outline-style: auto`) at rest while it reads them, below every author rule, so focus no longer makes an outline appear and Chromium lay out the page for each element: 4,000 links took 0.6 s and now take 0.17 s, with the same results. Elements in shadow trees, which a document style sheet does not reach, cost what they did.
- `rgaa-css-colors-paired` asks about a background color with no text color (`BACKGROUND_WITHOUT_COLOR`, 10.5.2), as the mapping does, where it failed it: a scan under the RGAA profile alone gave a failure that the same scan beside another profile gave as a question. RGAA 10.5.2's test asks for the `color` property, its methodology only for a computed color, which the browser's default gives; the "How to check" step says so. The other two findings still fail.
- `rgaa-link-state-colors-review` gives every link the style of the browser's focus ring (`outline-style: auto`) at rest for the time it reads the focus state, below every author rule as the browser's own ring is, so focusing a link no longer makes an outline appear, which cost Chromium a layout of the page per link: 4,000 links shown by color took 2.8 s, or 7.2 s in one paragraph, and now take 0.2 s, with the same results.
- `rgaa-link-state-colors-review` reads what it needs of each style rule (its color, text decoration and generated content, and its selector's parts) once, not once per link: the rule took 1.2 s on a saved fr.wikipedia article in Chromium and now takes 0.16 s.
- `rgaa-link-state-colors-review` reads once per parent whether it has text of its own, not once per link: 4,000 links in one `<div>` took 11 s in Chromium and now take 6 ms.
- `rgaa-link-state-colors-review` no longer says no style rule sets a link's color when a style sheet from another origin could not be read: in a browser, a computed color other than the browser's own link color is the author's, and the link is asked about for the unread sheet (`STYLESHEET_UNREADABLE`) rather than for the browser's visited color (`BROWSER_STATE_COLORS`). Without a browser, an unread sheet is asked about the same way.
- `rgaa-th-scope-row-col` reads a table's shape (spanning cells, rows, first row) once per table, not once per header with `scope`: a table of 4,000 cells took 0.7 s in Chromium and now takes 5 ms.
- `rgaa-html-elements-attributes-valid` reads the ids of a table's header cells once per table, not once per cell with `headers`: a table of 4,000 such cells took 1.7 s in Chromium and now takes 12 ms.
- The rules make their arrays with spread, not `Array.from`, which old libraries (Prototype, MooTools) replace. Prototype's gives an empty list for a `Set` or a `Map` iterator and counts a string by UTF-16 code unit, so on such a page `rgaa-moving-content-review` would have taken any animation for blinking and the label-in-name rules miscounted characters outside the Basic Multilingual Plane. With a core that scans such pages (the release after 1.15.0), they are scanned with the pack too; before, the scan stopped with `PAGE_BUILTINS_BROKEN`.
- The rules follow RGAA 4.1.2's revision notes: a layout table may have a `<colgroup>` (5.8.1), `basefont` is no longer a presentational attribute (10.1.2), and an `<svg role="img">`, or an SVG element with `role="img"`, named by its `<title>` passes (1.1.5, 1.1.1).
- A `<canvas>` with no role, name, fallback or link is asked about under 1.1.8 and 1.2.5 rather than failed under 1.1.8, since decorative canvases are common; an `<svg aria-hidden="true">` that keeps a `<title>` fails 1.2.4 and is asked about under 1.1.5 rather than failing both.
- Screen-reader-only text is no longer part of a visible label in `rgaa-field-label-in-name-sources`, `rgaa-link-label-in-name-sources` and `rgaa-form-button-label-in-name-sources`, which failed a link whose title repeated its visible text beside a hidden "Page active".
- `rgaa-presentational-attributes-absent` leaves out metadata and script elements, so `<link rel="mask-icon" color>` (a pinned tab's color) no longer fails 10.1.2.
- `rgaa-skip-link-placement` asks (`SKIP_LINK_POSITION_SHIFTED`) rather than fails when another page shows the skip link only higher or lower: content above it, such as a cookie banner or a message, pushes it down without moving it in the layout. A link more than 24px to the side still fails.
- `rgaa-orientation-content-parity` asks (`CONTENT_BEHIND_CONTROL`) rather than fails when content hidden in one orientation is opened there by a control shown in it (`aria-controls`, or `aria-expanded="false"` beside it), such as a menu collapsed behind a toggle: 13.9.1 lets the means of reaching content differ. A short text about the orientation itself ("rotate your device", in five languages) shown in one orientation only no longer fails as content missing from the other.
- `rgaa-page-zones-reachable` no longer passes a page whose header, navigation or footer it could not find: it asks about each block outside every area it found that holds links to other pages or places (`ZONE_UNIDENTIFIED`).
- The "How to check" steps of themes 8 to 10 give RGAA's verdict instead of deferring to the audit: markup in a shadow root is part of the generated source and fails 8.2.1 when it is as the report says; `<img role="presentation">` passes 8.2.1 with `alt=""` and fails without alt; text in the other reading direction fails 8.10.1 without `dir` whatever its length, and a `<bdi>` does not replace `dir`.
- The steps of themes 8 to 10 follow RGAA's text: a link's hover and focus states need a mark other than color as well as 3:1 (10.6.1); a heading's spoken name need not match its visible text, only be relevant (9.1.2); a current-page marker given only by color is 3.1's, not 10.9.1's; 10.4.2 asks only that all the text reach 200%; 8.7's particular cases, the main content zone of the glossary, a missing doctype under 8.1.3 and how to set the validator to an older doctype are spelled out.
- `rgaa-presentational-attributes-absent` allows width and height on a `<source>` in a `<picture>`, as on `<img>`: they give that image candidate's dimensions, which HTML added in 2021, after RGAA 10.1.2's list was written, and the pack reads the list, which predates them, as covering them. On any other `<source>` they fail.
- `rgaa-aria-list-item-roles` files a list whose items are numbered under 9.3.2 (`liWithoutListitemRoleOrdered`, `childWithoutListitemRoleOrdered`), any other under 9.3.1, and `rgaa-tooltip-review` asks about each tooltip once per test of 10.13 (`…Dismiss`, `…Hover`, `…Persist`), so each answer counts toward the one test it settles.
- Core's steps in RGAA's terms (`review.js`) are each filed under the facet of the test their findings go to, and their failure names that test: `css-hidden-focus` asks under 10.7.1 alone, a tab stop with no visible focus being 10.7.1's matter, and the list rules name 9.3.1 for a `<ul>` or `<menu>`, 9.3.2 for an `<ol>` and 9.3.3 for a `<dl>`, in RGAA's words rather than WCAG's.
- Core's steps for themes 8 to 10 follow RGAA's text: text spacing is checked with RGAA's values set by a user style sheet, which overrides the page's `!important`, at the widths the page is viewed, without WCAG's 320 pixels or 400 % and with no exception for text that does not wrap (10.12.1); a duplicate id in a shadow root fails 8.2.1 whether or not anything references it; a link's visited, active, hover and focus states are checked as 10.6.1's methodology asks; and different pages that share one title fail 8.6.1, a title being what lets a person find the page in the history or the tabs.
- `rgaa-doctype-valid` no longer fails every doctype outside the W3C's list of recommended ones, which RGAA does not name: it passes the published HTML and XHTML doctypes it knows, HTML 4.0 Strict, Transitional and Frameset, ISO/IEC 15445 HTML and XHTML Mobile Profile 1.0 to 1.2 among them; fails only a doctype whose name is not html, or the HTML5 form with a system identifier other than `about:legacy-compat`; and asks (`unknownPublicId`) about any other public identifier, for a person to look up under 8.1.2.
- Two of core's newer rules have rows in the mapping: `click-handler-keyboard-operable` asks under RGAA 7.3.1, since its condition 2 passes an element whose action another keyboard-operable control offers, and `moving-content-pausable` asks under 13.8.1 and 13.8.2. A test now fails when a rule core runs has no row.
- `rgaa-contrast-minimum` asks (`LOGO_TEXT_BELOW_THRESHOLD`) rather than fails about text that looks like part of a logo: RGAA 3.2's particular cases make logo and brand text not applicable, and whether text is a logo is found by a heuristic. It uses core's `logoText: 'ask'` setting.
- Core's `focus-not-removed-by-script` asks under RGAA 7.3.2 about an inline `onfocus` handler that calls `blur()`: a script must not remove focus from an element that receives it.
- `rgaa-css-colors-paired` leaves screen-reader-only text out (clipped, 1px with its overflow hidden, transparent): it is never drawn, so it shows no color to pair. A cookie panel's visually hidden heading failed 10.5.1 on every page of a site.
